feat: integrate search-parser service into RsDorDcApp

Wire up the RsDorDcApp to call the search-parser microservice before
sending queries to OpenSearch. This enables centralized query transformation
logic in the Ruby microservice.

Changes:
- Created searchParserService.js: Client for parser service API
  - parseSearchQuery(): Calls POST /parse endpoint
  - checkParserHealth(): Health check on startup
  - Graceful fallback to raw queries if service unavailable

- Updated RsDorDcApp component:
  - Added parserAvailable and parserError state
  - Test parser health on mount alongside ReactiveSearch
  - Modified handleSearchChange to call parser service asynchronously
  - Store parsed query in parsedQueryRef
  - Updated customQuery to use parsed query instead of raw value
  - Added warning alert when parser service unavailable

- Configuration:
  - Added VITE_SEARCH_PARSER_URL to env.template.sh
  - Default: http://localhost:4567
  - Docker network: http://search-parser:4567

- Documentation:
  - Created INTEGRATION.md with architecture and testing guide

The app gracefully degrades if the parser service is down, showing a
warning but continuing to search with raw queries.
